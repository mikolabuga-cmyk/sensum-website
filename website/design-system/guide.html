04 / MOTION

Movement with a purpose.

Hover the examples or focus them with Tab. Feedback uses ease-out; expansive movement uses cubic-bezier(.22, 1, .36, 1). Scroll reveals use viewport progress, not a fixed playback duration.

Reduced motion resolves text immediately and removes decorative drift and transitions. Test with the operating system’s reduced-motion setting. Scene choreography belongs to its section; the letter renderer is shared.

05 / VISUAL EFFECTS

One focal point at a time.

Hero atmosphere

Fine monochrome particles form a quiet perimeter around readable copy. Canvas is decorative and cannot receive pointer or keyboard focus.

Explore hero ↗

Service shapes

SVG point orbs appear on hover and keyboard focus. Cube, sphere, octahedron, and tetrahedron each have an intentional scale. Hidden on compact touch layouts.

Explore services ↗

Particle portraits

Depth-map WebGL geometry with subtle parallax. Always formed; no loading-photo flash. Three people share one renderer. Source-image fallback appears only if rendering fails.

Explore team ↗

Soft material

Selective header blur, quiet hairlines, rounded media, and a contained fluid CTA. These effects support hierarchy; they are not a default card treatment.

06 / BUILDING BLOCKS

Shared source. Real behavior.

The homepage and previews are composed from the same HTML partials. CSS and JavaScript are the production files. Storybook isolates each example in its own document so animation listeners are cleaned up when you switch stories.

NavigationPrimary CTAContact actionWork cardService rowCapabilitiesTeam switcher

Each complete section is available under Sections. Use the width control for 320px, 390px, tablet, and desktop previews. Scroll inside a scene to inspect its choreography. Product Clarity stays within its parent narrative because they share one scroll timeline.

npm ci
npm run storybook         # local library, port 6006
npm run components:build # compose static homepage + previews
npm run components:check # detect stale generated files
npm run build-storybook  # public Storybook build

Edit components/*.html, not the generated homepage. New variants require a documented use case; do not invent extra button types or states the website does not need.

07 / DESIGN SYSTEMS OPS

Keep the system honest.

Every change is reviewed against the running website, token ownership, keyboard interaction, mobile layout, reduced motion, and fallbacks. Findings are classified as keep, adjust, or remove, with evidence and severity.
